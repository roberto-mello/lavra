# Lavra v0.7.8 release notes

**Release date:** TBD

This release rolls up all unreleased work from the previous `v0.7.7` and `v0.7.8` drafts.

## Highlights

### Epic execution now supports a cheaper sequential mode

When you run `lavra-work` on an epic with multiple ready beads, you can now choose:

1. Sequential mode
2. Parallel mode

Sequential mode runs beads one at a time in the main context and runs review once at the end. For small and medium epics, this is usually much cheaper in tokens.

You can force behavior with flags:

- `--parallel`
- `--no-parallel`

### Review findings now get triaged before creating beads

Not every review finding needs a new bead. Lavra now applies inline-fix triage in both single-bead and multi-bead flows.

- P3 and cosmetic findings in already-open context can be fixed inline
- P1/P2, multi-file, or broader fixes still become beads

This keeps the process strict, but cuts busywork.

### `.lavra/` path handling is now stable from any subdirectory

Commands and skills that touch `.lavra/*` now resolve project root first, then use root-based paths. This fixes silent failures when a subagent changed directories mid-run.

## Workflow and planning improvements

### `lavra-work` router lives in a skill and documents shared guarantees

Router logic now lives in `skills/lavra-work/SKILL.md`, with the command acting as a thin shim. The router also explicitly documents inherited guarantees such as goal verification, deviation handling, session handoff, and commit policy.

### `lavra-design` research gate now makes token cost explicit

Before fan-out research, the flow now shows clear choices including a token-efficient default path to skip research for that run.

### Deferred anti-patterns now require a durable record

When Lavra spots the same risky code pattern again, but fixing it would require work outside the current bead, a `DEVIATION` comment alone no longer passes the gate. You now need either:

- a `MUST-CHECK` entry, or
- a proposed project rule update

This makes sure future runs see the warning.

## Memory quality and recall reliability

### Curated active memory set for recall

Recall now prefers a curated local memory set built from append-only `knowledge.jsonl`:

- `knowledge.active.jsonl`
- `knowledge.active.db`

This improves recall quality and reduces token waste from duplicate and stale entries.

### Background sanitizer with audit trail

`memory-sanitize.sh` now runs in the background and writes a local audit file:

- `knowledge.audit.jsonl`

It also performs anchor and drift checks to flag stale memory candidates.

### Go helper path for faster local sanitization

If `go` is available, Lavra builds and uses a local sanitizer binary in `.lavra/memory/`. If not, fallback behavior still keeps recall working.

## Installation and packaging improvements

### Installers now require explicit `bd init`

Installers no longer auto-run `bd init`. If `.beads/` is missing, they stop and tell you exactly what to run.

### Clear warning when `sqlite3` is missing

If SQLite is not installed, installers now warn that recall will fall back to slower linear JSONL search.

### Context7 confirmation is now shown in install summary

Install output now confirms Context7 MCP setup when applied.

### Smaller npm package

Generated platform directories are no longer shipped in the npm tarball:

- `plugins/lavra/opencode/`
- `plugins/lavra/gemini/`
- `plugins/lavra/cortex/`

### Conversion scripts now rewrite hook paths consistently

Platform conversion now updates hook path references as well, not just skill paths.

## New feature: Codex support

Lavra now supports Codex as a first-class install target.

### How to install

```bash
npx @lavralabs/lavra@latest --codex            # project install
npx @lavralabs/lavra@latest --codex --global   # global install
```

### How to use it in Codex

Use Lavra through Codex skills:

- `$lavra-plan ...`
- `$lavra-work ...`
- `$lavra-review ...`

In the current direct-install path, Codex uses `$lavra-*` skill invocation rather than `/lavra-*` slash commands.

### What this release includes for Codex

This release also hardens the Codex path:

- full uninstall parity (`uninstall.sh --codex` and runtime-aware `npx ... --uninstall`)
- safer hooks merge behavior (preserves `check-memory` in existing `~/.codex/hooks.json`)
- deterministic generated artifacts (stale generated command/agent files are removed on regen)
- Codex-targeted path and invocation normalization in generated files (`.codex/*`, `$lavra-*`)

## Upgrading

```bash
bunx @lavralabs/lavra@latest
```

No breaking changes.
